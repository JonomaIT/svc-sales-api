# svc-sales-api

Sales API of the JonomaIT lab: takes a sale, stores it and hands it over to processing ([`svc-sales-worker`](https://github.com/JonomaIT/svc-sales-worker)), active in two regions. A JonomaIT rewrite of the sales workload of the LINUXtips containers course, on the platform's contracts.

```
client ──► sales.joshuel.com.br ──► Cloudflare ──► ingress (Load Balancer) ──► ALB ──► svc-sales-api
                                                                                         │
                         ┌───────────────────────────────────────────────────────────────┤
                         ▼                                                               ▼
        DynamoDB "sales" (global table)                             SNS "sales-created" (this region)
        us-east-1 ⇄ sa-east-1                                       ──► the sales-processing queue of EVERY region
```

| Endpoint | Answer |
|---|---|
| `POST /sales` `{"product": "coffee", "amount": 12.5}` | `201`, the sale with `status: PENDING` (it becomes `PROCESSED` when the worker of the ACTIVE region handles it) |
| `GET /sales/<id>` | `200` the sale, `404` |
| `DELETE /sales/<id>` | `204`, `404` |
| `GET /info` | task, region and region state (`ACTIVE` / `PASSIVE`) |
| `GET /health` | `ok` (ALB health check; never calls AWS) |

CORS: only the sites in `ALLOWED_ORIGINS` (`https://vendas.joshuel.com.br`, [`web-sales`](https://github.com/JonomaIT/web-sales)) may call it from a browser; `X-Region` is exposed to them.

Money is never a float: amounts are read as decimals, rounded half up to cents and returned as text (`"12.50"`). Every answer carries `X-Region`.

## What the platform gives it

The app has no Terraform and no IAM. It declares its data in [`deploy/data.hcl`](deploy/data.hcl) (ADR-011) and receives, in each region:

| Variable | Value |
|---|---|
| `TABLE_SALES` | `jonomait-prd-svc-sales-api-sales` |
| `TOPIC_SALES_CREATED` | the topic ARN of its region |
| `REGION_STATE_PARAMETER` | where the region state lives (ADR-012) |

Its task role may only use that table and publish to that topic (the data runner's `…-data-access` policy).

If the event cannot be published, the sale is removed and the client gets `503` (a sale nobody will process must not stay stored). A transactional outbox (DynamoDB Streams to the topic) would make it atomic: a next step.

## Pipeline

`ci.yml` calls `build-push` from `pipelines`: the image build runs the unit tests (a failing test fails the build), Trivy scans the image, and `main` pushes it to the platform registry tagged with the commit SHA. Dependencies are pinned with hashes (`requirements.txt`, generated by `pip-compile --generate-hashes` from `requirements.in`); Dependabot keeps them current.

## Deploy

**The pipeline deploys** (`deploy-app` of `pipelines`): on `main` when the `AUTO_DEPLOY` org variable is `true` (the lab is up), or by hand in *Actions → CI → Run workflow* (`destroy` removes the app, data last). It runs, in the production GitHub Environment, the steps below and then the smoke test, with the image of the commit.

Order: **data first** (the table and topic must exist before the app starts), then the app in each region. The worker's data comes after this app's data (it subscribes to this topic).

By hand, the same steps:

```bash
# data: once per account, every region in one state
cd pipelines/terraform-runner/data
terraform init -backend-config=../../../organization/backends/production.tfbackend -backend-config=key=production/cross-region/data/svc-sales-api
terraform apply -var-file=../../../svc-sales-api/deploy/data.hcl \
  -var environment=production -var name=svc-sales-api -var 'regions=["us-east-1","sa-east-1"]'

# app: once per region in deploy/env/production.tfvars
cd ../ecs
terraform init -backend-config=../../../organization/backends/production.tfbackend -backend-config=key=production/us-east-1/apps/svc-sales-api
terraform apply -var-file=../../../svc-sales-api/deploy/app.hcl -var-file=../../../svc-sales-api/deploy/env/production.tfvars \
  -var environment=production -var region=us-east-1 -var image=151995620066.dkr.ecr.us-east-1.amazonaws.com/svc-sales-api:<sha>
```

Smoke test after a deploy: `hurl --test --variable host=https://sales.joshuel.com.br tests/smoke/sales.hurl`.
